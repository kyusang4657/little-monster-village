# Android 제작·전달 기준

## 이번 목표

사용자가 확인한 첫 테스트 대상은 **Android 휴대전화**입니다. APK를 만들어 사용자가 직접 설치해 보는 단계이며, 스토어 등록이나 공개 배포는 이번 작업 범위에 포함하지 않습니다.

새 프로젝트의 제안 경로는 Godot 4.x 안정 버전, GDScript, 단순한 실시간 3D, Compatibility 렌더러입니다. 넓은 기기 범위를 우선하는 시작안으로 선택했습니다. 실제 기기의 성능은 별도로 측정해야 합니다. Compatibility는 기본 3D와 저사양·구형 모바일 하드웨어를 지원하는 경로로 설명되어 있습니다. [Godot 렌더러 설명](https://docs.godotengine.org/en/stable/tutorials/rendering/renderers.html)

## 내보내기 준비

제작 시 사용한 Godot의 정확한 버전과 같은 버전의 내보내기 템플릿을 맞추세요. Android 도구의 설치 상태를 먼저 확인하고, 선택한 엔진 버전에 맞는 공식 내보내기 안내를 따르세요.

확인한 공식 문서는 OpenJDK 17과 Android SDK 설정을 안내합니다. SDK 세부 패키지 버전은 문서와 엔진 버전에 따라 달라질 수 있으므로 이 패키지의 숫자를 복사해 고정하지 마세요. 프로젝트 제작 시점에 해당 버전의 안내를 확인하고 설치한 버전을 기록하세요. [Godot Android 내보내기](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html)

테스트용 APK와 스토어 제출용 AAB는 목적이 다릅니다. 이번에는 휴대전화 설치 테스트용 APK를 전달합니다. [Android Developers의 Godot 내보내기 안내](https://developer.android.com/games/engines/godot/godot-export)

## 프로젝트 전달 기준

- 가로 화면, 한국어 글꼴과 실제 UI 텍스트.
- 인터넷 없이 새 게임·불러오기·건설·전투 가능.
- 선택한 패키지 ID와 서명 설정을 기록하고 후속 테스트 빌드에서도 일관되게 유지.
- 디버그 APK임을 파일명과 README에 명시. 출시용 비밀 키·계정 정보는 소스에 넣지 않음.
- 해상도·노치 안전 영역에 맞는 UI 배치. 16:9 그림을 화면 비율에 관계없이 강제로 늘리지 않음.
- 설치·실행·저장 파일 위치·초기화 방법을 사용자 관점에서 설명.
- 테스트 빌드를 업데이트하려면 먼저 저장 데이터 보존과 같은 패키지 ID/서명 사용 여부 확인. 무조건 기존 앱 삭제를 안내하지 않음.

## 기기 확인

사용자 휴대전화의 모델·Android 버전은 아직 알 수 없습니다. 제작 AI가 기기에 접근할 수 있으면 기록하고 직접 확인합니다. 접근할 수 없다면 아래 항목을 ‘사용자 실기기 확인 필요’로 남깁니다.

- 설치와 첫 실행, 한국어 표시, 가로 화면 유지.
- 손가락으로 건물 선택·이동·회전·취소·배치.
- 확대/축소·배경 이동과 UI 터치의 충돌 여부.
- 전투 일시정지·백그라운드 전환·복귀.
- 확정 배치와 진행도의 재실행 복원.
- 10분 플레이 중 멈춤·발열·배터리 부담, 전투 중 프레임 속도.

30FPS와 최소 48dp 터치 영역은 이 프로젝트의 초기 목표입니다. 실제 측정 전 달성했다고 표시하지 않습니다. 테스트 기기·방법·결과를 함께 기록하고, 성능이 낮으면 식물 개수·그림자·재질 복잡도부터 줄입니다.

## 외형 작업과 빌드가 막힐 때

최종 3D 모델이 없어도 임시 입체 모델로 플레이 구현을 계속합니다. Android 빌드 도구가 없으면 작동하는 프로젝트를 먼저 보존하고 설치가 필요한 항목을 구체적으로 기록합니다. 이미지 시안만으로 APK 제작이 끝났다고 보고하지 않습니다.

공식 문서 확인일: 2026-09-27. 이 문서는 엔진 설치나 APK 생성을 실행한 기록이 아닙니다.
