# 결정 사항과 이번 기본안

## 사용자와 정한 방향

- Android 휴대전화에 설치해 첫 버전을 테스트.
- 가로 화면, 높은 고정 쿼터뷰, 밝고 아기자기한 그래픽.
- 인간 영웅이 아닌 마물 진영의 마을을 성장시킴.
- 건물과 울타리를 배치하고, 가끔 나타나는 인간 적을 방어.
- 단순한 조작과 반복하고 싶은 플레이를 목표로 함.
- 생성형 AI에 구체적인 이미지와 지시를 넘겨 제작하려는 방식.
- 작은 게임의 출시와 수익성은 장기 목표.

## 이번 지시서가 채운 제안값

아래는 사용자가 개별 숫자까지 승인한 규칙이 아니라, 제작 AI가 멈추지 않고 시작하도록 정한 첫 구현 기본안입니다.

| 항목 | 기본안 |
| --- | --- |
| 엔진·자산 방식 | Godot 4.x 안정 버전, GDScript, 실시간 3D |
| 렌더러 | Compatibility |
| 마을 | 14×10칸, 초기 건물 여섯 동 |
| 카메라 | 정사영, 방위 약 45°·내려다보는 각도 약 50°, 조정 가능 |
| 경제 | 목재 1종, 시작 100, 초당 1, 상한 500 |
| 건설 | 주택 30, 방어탑 80, 내부 울타리 한 변 2 |
| 성장 | 방어탑 Lv.2 강화 60, 공격력 10→15 |
| 전투 | 준비 후 사용자 시작, 습격 세 단계, 기사 4/6/8명 |
| 울타리 | 길을 막는 장애물, 파괴 없음, 성으로 가는 경로 완전 봉쇄 금지 |
| 문과 길 | 문은 항상 열림, 흙길은 장식이며 잔디 이동 가능 |
| 패배 | 성 체력 복원, 마을 유지, 같은 단계 무료 재도전 |
| 저장 | 기기 안 저장, 오프라인 생산·전투 중간 복원 제외 |

실제 수치는 config/prototype-defaults.json을 단일 기준으로 사용합니다. 테스트 결과에 따라 숫자를 바꿔도 되지만 변경 이유와 결과를 기록해야 합니다. 사용자가 나중에 정하는 요구는 이 제안보다 우선합니다.

## 첫 버전에서 일부러 줄인 부분

- 원정 지도·원정 스테이지는 이후 단계입니다. 이번의 세 단계는 자기 마을에서 막는 습격입니다.
- 주택은 첫 버전에서 꾸미기용이며 인구·고용 효과를 추가하지 않습니다.
- 고블린 일꾼은 분위기용입니다. 망치 공격 자세 그림이 있다고 자동으로 근접 전투를 구현하지 않습니다.
- 성은 Lv.1 고정, 초기 벌목소도 한 채 고정 수량입니다. 성 확장과 여러 생산 자원은 이후로 남깁니다.
- 문 공성·울타리 파괴·서버·대전·클랜·광고·결제·캐릭터 뽑기는 제외합니다.

## 출시·수익성으로 이어갈 판단

첫 버전은 수익성을 입증하는 제품이 아닙니다. 먼저 처음 플레이한 사람이 건설과 방어를 이해하는지, 배치를 바꿔 다시 해보고 싶은지, 다음 습격을 기다리는 시간이 답답하지 않은지 관찰합니다. 실행 속도·사용한 조작·막힌 부분·다시 하고 싶은 이유를 짧게 기록하면 됩니다.

이 단계에서 광고나 결제 수치를 가정해 수익을 약속하지 않습니다. 플레이가 성립한 뒤 콘텐츠 확장·수익 모델·스토어 준비를 별도 작업으로 정합니다.

## 자료 충돌의 정리

새 공통 규칙 → 새 아트 가이드의 고정 구조 → 개별 자산 이미지 → 전체 화면 → 과거 생성 프롬프트 순으로 읽습니다. 수치는 새 config가 기준입니다.

- 14×10은 마을 기본안, 과거 울타리 6×3은 별도의 연결 시험 예시입니다. 과거 프롬프트의 5×3은 현재 규칙으로 쓰지 않습니다.
- 벌목소는 최종 마을 화면처럼 왼쪽 뒤를 기본 위치로 잡았습니다.
- 건설 화면은 기존 주택 이동의 예시입니다. 새 구매는 별도의 비용 확인·확정 흐름으로 구현합니다.
- 모든 원본 그림은 참고 시트이며 모델·리그·연속 애니메이션·실제 UI 소스가 아닙니다.
- 과거 자료에 없던 정확한 맵 좌표와 수치는 이번에 작성한 제안입니다. 이미지에서 측정한 값이 아닙니다.
