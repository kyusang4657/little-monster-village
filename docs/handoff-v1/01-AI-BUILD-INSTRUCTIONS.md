# 제작 AI에게 전달할 전체 지시

당신은 이 자료를 바탕으로 실제로 실행되는 게임을 제작하는 개발자입니다. 설명이나 기획 제안에서 멈추지 말고, 아래 범위의 프로젝트를 구현하고 가능한 검증과 Android APK 내보내기까지 진행하세요.

## 목표와 우선순위

Android 휴대전화에 설치할 수 있는 가로 화면의 작은 마물 마을 게임을 만드세요. 플레이어가 목재를 얻고, 건물을 추가하거나 옮기고, 인간 기사의 습격을 자동 방어한 뒤 보상을 받아 다음 준비를 할 수 있어야 합니다.

우선순위는 **기능이 이어지는 플레이 → 터치 조작 → 외형의 통일 → 세부 장식**입니다. 한 장짜리 마을 그림 위에 버튼만 올려놓은 결과는 마을 건설 게임의 완성이 아닙니다.

사용자가 확정한 방향은 마물 진영, 귀여운 그래픽, 높은 고정 시점, 가로 화면, 간단한 조작, 마을 건설과 방어, Android 실기기 테스트입니다. 엔진과 세부 수치는 이 패키지에서 제안한 기본안입니다.

## 시작 전에 읽을 파일

1. 02-GAME-RULES.md
2. config/prototype-defaults.json 및 config/initial-layout.json
3. 04-ART-GUIDE.md와 asset-manifest.json의 이미지
4. 03-ACCEPTANCE.md
5. 05-ANDROID-DELIVERY.md

수치의 단일 기준은 config입니다. 동작 규칙은 02-GAME-RULES.md, 자산 고정 구조는 04-ART-GUIDE.md를 따릅니다. 충돌 시 이 새 제작 규칙을 과거 source-notes보다 우선합니다. 과거 프롬프트의 모델 생성 지시나 단계별 ‘다음 이미지’ 문구는 지금 수행할 작업이 아닙니다.

## 기술 기본안

새 프로젝트라면 Godot 4.x 안정 버전, GDScript, Compatibility 렌더러, 실시간 3D로 시작하세요. 설치된 안정 버전이 적합하면 사용하고, 정확한 엔진 버전과 일치하는 내보내기 템플릿을 기록하세요. 기존 게임 프로젝트가 있으면 먼저 확인하고 무관한 작업을 덮어쓰지 마세요. 다른 엔진의 진행 중 프로젝트를 임의로 갈아엎지 말고 기존 환경으로 요구사항을 달성할 수 있는지 판단하세요.

건물과 캐릭터는 처음부터 개별 오브젝트여야 합니다. 간단한 메시와 재질로 기능을 구현한 뒤 지붕·성문·통나무·깃발·진영 색을 기준 시트에 맞추세요. 이미지 10장은 모델이나 애니메이션 파일이 아닙니다. 런타임 생성형 AI나 유료 이미지 API를 게임 필수 의존성으로 추가하지 마세요.

최초 구현은 오프라인 싱글플레이입니다. 서버·로그인·광고·결제 SDK는 사용하지 않습니다. 사용자 기기의 연락처·위치·카메라 권한도 필요 없습니다.

## 반드시 들어갈 기능

- 한국어 UI와 가로 화면, 높은 정사영 카메라, 화면 이동과 확대/축소.
- 초기 14×10 마을: 성 1, 주택 2, 벌목소 1, 방어탑 2, 울타리와 열린 정문.
- 셀 기반 건물 배치, 90도 회전, 이동 미리보기, 취소와 확정.
- 목재를 써서 주택·방어탑·내부 울타리를 추가하는 작은 건설 메뉴.
- 방어탑 Lv.1→Lv.2 강화. 모델은 같은 기본 구조로 유지하고 레벨 배지로 구분 가능.
- 목재 자동 생산과 상한, 상태별 시간 처리.
- 준비된 습격의 예고와 ‘방어 시작’ 버튼. 사용자가 준비하기 전 자동으로 전투를 시작하지 않음.
- 기사 한 종류의 이동과 성 공격, 방어탑 자동 표적 선택·조준·발사·피해.
- 습격 3단계, 승패와 보상, 마을 유지, 무료 재시도.
- 일시정지와 앱 백그라운드 전환 처리.
- 확정 배치·목재·강화·진행도의 로컬 저장과 불러오기.
- Android 설치용 APK와 프로젝트 소스.

새 건물 구매 UI, 습격 예고, 결과 화면은 별도 완성 이미지가 없습니다. 기존 건설 화면의 아이보리 패널·보라색·초록색 버튼을 재사용해 간단히 구현하세요.

## 작업 순서

### 1. 작동하는 뼈대와 Android 경로 확인

프로젝트를 만들고, 초기 마을과 카메라·한국어 UI를 표시하세요. 가능한 빨리 임시 화면이라도 Android 내보내기를 확인해 마지막에 빌드 환경 문제가 발견되지 않게 하세요. 외형 모델을 완성하느라 배치 기능을 미루지 마세요.

### 2. 배치·경제·저장

공통 격자 데이터를 기준으로 점유, 울타리 변, 비용, 취소, 회전, 통로 검사를 구현하세요. 원래 위치 복원과 비용 차감은 확정 시점 기준입니다. 마을 편집 후 종료·재실행해 저장을 확인하세요.

### 3. 첫 습격

네 명의 기사와 기본 두 방어탑으로 이동→조준→피해→제거→승리 또는 패배가 끝까지 이어지게 만드세요. 성 주변의 공격 가능한 칸을 목표로 삼고, 막힌 길과 사라진 공격 대상도 처리하세요.

### 4. 반복 플레이와 외형

보상, 다음 습격 예고, 강화, 패배 재도전을 연결한 뒤 3단계까지 진행하세요. 기준 시트에 따라 모델을 다듬고 걷기·공격·피격을 간단히 표현하세요. 그림 전체를 잘라붙여 움직임을 흉내내는 방식으로 대체하지 마세요.

### 5. 검증과 전달

03-ACCEPTANCE.md의 주요 기능과 Android 항목을 확인하세요. 가능한 자동 검사는 배치 원자성, 경로 검사, 비용·보상 중복, 저장 복원처럼 결과가 중요한 규칙에 집중하세요. 실제 터치·가독성·성능은 기기에서 따로 확인하세요.

실기기 접근이 없으면 APK 생성까지 진행하고 실기기 항목은 미검증으로 남기세요. 빌드 환경이 없으면 프로젝트와 확인된 범위, 막힌 정확한 원인과 필요한 다음 조치를 전달하세요. APK 또는 실기기 검증이 빠졌는데 전체 완료라고 보고하지 마세요.

## 전달물

- 편집 가능한 전체 게임 프로젝트와 필요한 자산.
- Android 설치용 디버그 APK. 스토어 출시 파일이라는 뜻은 아닙니다.
- 사용한 엔진 버전·내보내기 설정·필요한 도구 목록.
- 실행·설치·조작 방법을 적은 README.
- 실제 실행 화면: 마을, 건설 미리보기, 전투, 결과.
- 테스트 결과: 통과·실패·미검증과 근거.
- 변경한 설정 수치, 원래 제안과 달라진 이유, 남은 문제.
- 저장 데이터 형식과 초기화 방법.

초안·계획·버튼 모형을 완성으로 보고하지 마세요. 작업 중 확인되지 않은 사항은 ‘미검증’으로 구분하고, 이미지 시안과 실제 실행 화면도 명확히 구분하세요.
